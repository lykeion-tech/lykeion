# Task 5 — read-only lab MCP tools

Implemented and verified on codex/aristotle. The server mounts stateless streamable MCP at /mcp/lab. The server identity is lyk_lab. Its three tools are search, read and links.

## Authority and evidence

- Route requires a live agent-run bearer with aristotle:ask. Every tool derives the requester from the current running Aristotle run joined to its chat (workspace + owner); there are no client-supplied workspace, user or run selectors. Identity lookup runs as the run; all facts and writes run in InWorkspace(ws, requester). The locked run/token/attempt, still-granted scopes, chat binding and current membership are checked for every call. The member row stays locked through evidence logging. Responsible user is not substituted for requester.
- Claim-token issuance now explicitly excludes Aristotle from the generic caller-token path even when connectors were requested. Generic add-on MCP servers and connector claims are excluded too. Other run kinds retain their existing scopes. A service integration test invokes the actual token issuance used by Claim, with a real dispatched Aristotle row, and checks all minted rows; it deliberately supplies a nonempty workspace-connector flag.
- Search accepts at most 20 candidates (10 by default), rereads each result under the requester, drops absent/foreign/stale candidates, deduplicates and returns only ref/kind/live title. Nil index and failed embed/Redis both return “search is unavailable; read and follow links instead”. Neither internal error details nor operator credentials are returned. Index I/O holds no lifecycle locks; the final read rechecks access, including token-scope changes and membership removal during retrieval.
- Read uses the same live projections and lesson citation guards as maintenance. The shared baseline excludes private Team manifests even for the uploader; safe assigned-Team metadata remains. Coresearch relations are not queried. Hidden services and Coresearch uploads are excluded from attachment metadata. A synthetic attachment call/preview requires a currently linked file on the correct card and matching record key, including for search, links, lessons and indexing. Study links also respect that filter.
- Links resolves each destination live and accepts a page size up to 20 (default 20). links(workspace:context) provides a derived directory of studies or lessons via the directory argument. Pass next_after as after to continue, including after an empty page of stale lesson candidates. The directory is navigation, not workspace evidence: it does not change workspace citation versions as new studies are created.
- lab_read now logs each actual access, including repeat reads and distinct incoming edges. via='read' means a direct read, 'search' a search hit, 'links' the opened origin, and a canonical source ref means the followed edge source → ref. The transaction commits all returned hits and evidence together. Rejected/stale/foreign candidates are not logged. 0052 alone was amended to replace the old (run, ref) uniqueness constraint with an identity primary key and indexed (run, ref). The existing DOWN drops the entire owning table, index and owned sequence. The review also adds bounded navigation indexes and a numeric lesson cursor in 0052. No new migration. For Show evidence, order by id; group by ref only when presenting a deduplicated list and retain incoming edges.

## Full-text evidence and limits

- read(ref, section?, offset?) returns the live fact and, for eligible record blobs, UTF-8 text in up to 128 KiB per page. Follow blob.next_offset for the next page; sections names the available body, error or packages sections. Stored record body remains separate, including inline code, truncated call/run previews and metadata.
- Allowed blob paths are the card's content-addressed blobs, live study output files allowed by the member download lookup, and the .text sibling of a currently linked and readable study file (extracted PDF/text, or the archive manifest). All require a blob.created event on this workspace/card and current record linkage. Blob I/O runs outside lifecycle locks; live authorization, reference/version and the exact selected blob key are checked again before returning/logging. Unknown/mismatched keys are refused.
- Binary content has no invented text; absent storage or a missing blob returns a clear full-text-unavailable note alongside the stored fact. Archive entry bodies, binary decoding and OCR are not implemented; this uses precisely the evidence extracted at study upload. Storage has no ranged-read API, so later pages skip preceding bytes under a 20-second timeout. This reads complete accessible UTF-8 evidence page by page, not an unbounded memory allocation. The Redis index still indexes the shared PostgreSQL fact baseline (including the stored preview), not every blob page.
- The fact versions for immutable records retain the existing live/superseded contract. Study, decision and workspace fact versions retain their existing projections; issuing tools does not create facts or change their versions.
